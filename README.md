# 8005 AGV 仓位 IO 仿真器

本仓库是8005 AGV仓位模拟器的正式开发仓库。当前提交由原型目录`SQCD_8005AGV_Simulator`迁移而来，作为双方开始协议对接前的模拟器初始代码基线。

当前版本用于在没有真实康耐德 `C2000-A2-KDDA0A0-AD6` IO模块时，模拟8仓位AGV的继电器DO、锁反馈DI、光幕DI、仓门和货物状态。

当前实现提供Modbus TCP模拟接口。后续如果[`8005-agv-protocol`](https://github.com/trytoreachpeak0/8005-agv-protocol)确定`HTTP/JSON + ISlotIoProvider`方案，将以协议仓库为唯一依据增量增加适配层；当前接口不应被视为最终共享协议，也不代表真实硬件认证结果。

## 运行

```powershell
dotnet run --project .\src\SQCD_8005AGV_Simulator\SQCD_8005AGV_Simulator.csproj
```

程序默认自动监听：

- IP：`127.0.0.1`
- 端口：`1502`
- Unit ID：`0xFF`
- DO PDU 地址：`100～115`
- DI PDU 地址：`200～215`

修改输出目录中的 `simulator.settings.json` 或源项目中的同名文件即可调整点位、极性和脉宽。

## 已实现 Modbus 功能码

| 功能码 | 功能 |
| --- | --- |
| `0x01` | 读取 16 路 DO |
| `0x02` | 读取 16 路 DI |
| `0x05` | 写单路 DO，ON=`0xFF00`，OFF=`0x0000` |
| `0x0F` | 批量写 DO，LSB-first |

DO 原始值 `1` 表示继电器 COM 与 N.O. 闭合，DI 原始值 `1` 表示输入与 GND 短接。锁反馈和光幕的业务极性由配置决定。

当前现场确认的默认极性为：

| 状态 | DO/DI原始值 | IO模块指示灯 |
| --- | ---: | --- |
| 开锁输出未动作 | DO=0 | 不亮 |
| 锁已锁上 | 锁反馈DI=1 | 亮 |
| 锁已打开 | 锁反馈DI=0 | 不亮 |
| 仓位为空 | 光幕DI=1 | 亮 |
| 仓位有货 | 光幕DI=0 | 不亮 |

程序启动和安全 Reset 后固定为：全部 DO=0、全部仓门关闭、全部仓位为空、锁反馈DI=1、光幕DI=1。开锁使用模块硬件 Pulse 模式。

## 测试

测试项目不依赖第三方测试框架，可以直接运行：

```powershell
dotnet run --project .\tests\SQCD_8005AGV_Simulator.Tests\SQCD_8005AGV_Simulator.Tests.csproj
```

测试覆盖安全初始态、Pulse 自动断开、装料关门闭环、单路/批量写、DI 位序和异常响应。

## 故障状态说明

界面会同时显示两类状态：

- `货物事实/仓门`：仿真器内部的真实物理状态，不直接通过 Modbus 暴露。
- `锁反馈/光幕`：车载端通过 Modbus 读取的传感器 DI。

选择“固定0/固定1”后，传感器 DI 被强制覆盖，但内部货物和仓门仍可正常变化，用于构造“货物已放入但光幕未检测到”等故障。此时对应仓位会显示红色边框、“反馈异常”徽标和具体矛盾原因，顶部显示全局故障提示；被选中的固定值按钮也会以红色背景标识。

`安全 Reset` 会清除全部反馈覆盖、通信不响应故障、Pulse/反馈延迟任务，并恢复门关、空仓、已锁、无遮挡和全部 DO=0 的初始状态。

## 日志显示

Modbus 客户端通常会按固定周期连续读取 FC01/FC02。仿真器默认正常响应这些请求，但不把每次周期读取逐条加入运行日志，避免日志快速滚动和频繁刷新界面。需要检查读取报文时，可以勾选日志栏中的“记录周期读取（FC01/FC02）”；取消“自动滚动”后，可以停留查看已有日志。连接、写 DO、异常和人工操作日志始终保留。

写 DO 的日志按照实际时序显示：先记录收到的 FC05/FC0F 命令，再记录 DO 原始值、继电器状态及输出模式；Pulse 到期后以“开锁输出结束”记录 DO 自动恢复，锁反馈 DI 实际更新时也会单独记录已解锁或已锁上。

界面默认使用 4×2 仓位布局和 150px 日志区，在 1440×900 初始窗口中可以完整显示 8 张正常状态仓位卡片。仓位区与日志区之间的分隔线可以上下拖动；窗口较小或故障详情展开后，仓位区保留独立纵向滚动。
